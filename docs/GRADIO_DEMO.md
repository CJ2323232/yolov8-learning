# 本地Gradio演示：五模型、明细与同图对照

2026-10-30更新。沿用原训练权重与推理算法，不重新训练，不改变既有成绩或历史融合阈值。

## 启动

Mac在Finder双击项目顶层 `01_启动安全帽检测.command`。如果旧版服务仍在原终端运行，按一次Control+C结束旧服务，再双击入口；刷新旧进程的网页不会加载新的Python代码。

也可在已激活的**应用环境**中，从仓库根目录运行：

```bash
python app.py
```

应用清单要求Python≥3.12。新环境安装见 [ENVIRONMENTS.md](ENVIRONMENTS.md)，Demo依赖为 `requirements-gradio.txt`；本次未安装或升级现有包，不应为Demo重装原Windows训练环境。

默认绑定本机127.0.0.1，`share=False`，不创建公网分享。设备默认按原应用选择MPS/CUDA/CPU；可显式 `YOLO_DEVICE=cpu python app.py`。Windows CMD可先 `set YOLO_DEVICE=0` 再执行 `python app.py`。本次真实接口验收使用CPU，不是CUDA/MPS性能测试。

## 单图检测

1. 上传没有预测框和文字的原图。`person`是未戴帽头部，不是全身行人；`hat`是戴安全帽头部。
2. 从已核验可用的权重中选择模型。有P2权重时默认P2、普通640、conf=.25；只有历史权重时明确显示历史方案，不拿它冒充新模型。
3. 点击“开始检测”，查看真实画框图、逐框表及实际运行信息。
4. 下载CSV或JSON；图片也可通过结果区下载按钮保存。

图片面板限定显示高度，竖图也能同时查看参数和结果；这只改变网页布局，预测和导出仍使用原图像素坐标。

五组独立选项：标准版、标准+P3-CBAM、P2、P2+P3-CBAM、P2+P2-CBAM。来源为 [release_manifest.json](../models/release_manifest.json) 中的相对路径和SHA256；路径覆盖仍可使用 `YOLO_STANDARD_MODEL_PATH` / `YOLO_P2_MODEL_PATH` 等对应环境变量。外部指定路径只在界面/导出中显示文件名，不抄出个人目录。

“模型文件与可用状态”列出缺失、未登记或哈希错误。不可用模型不进入选择列表；融合需要标准版/P2都可用，对照需要至少两份正式实验权重。添加或移动权重后重启应用刷新状态。不会自动下载替代模型。[五组权重尚未公开下载](../models/README.md)；合法取得对应文件是新用户的前置条件。

模型仍然按需加载和复用，不在启动时加载五个YOLO实例。旧训练登记失效会提示并跳过，不阻止其他正式权重使用；显式自选路径失效会明确提示。

## 参数与显示

| 功能 | 实际行为 |
|---|---|
| 普通检测 | 支持640/960及NMS IoU调节，默认.7 |
| SAHI | 锁640与模型NMS IoU=.7；切片640×640、横纵重叠.2、包含整图预测、跨片GREEDYNMM/IOS=.5；单块回退普通检测 |
| 历史NMS/WBF融合 | 固定640整图、模型NMS IoU=.7、候选conf=.01、融合IoU=.55；最终阈值分别.30/.17 |
| 类别/置信度/编号显示 | 只影响绘图，不删除或重算预测；编号对应逐框表 |

SAHI跨片IOS不是YOLO NMS IoU，也不是评价匹配IoU。普通检测改过的IoU不会泄漏给SAHI。SAHI的300上限是每次模型调用的候选上限，跨片合并后未额外截断；单块回退普通时最终上限仍为300。JSON中区分 `per_model_max_det` 和 `final_max_det`。

标准版单模型原验证选择阈值.29、P2为.25；CBAM三组的.25是共同实验比较默认，未分别校准。历史融合阈值有独立来源，不被统一改成.25。改变阈值、尺寸或NMS后会标为自定义设置，不套用原报告成绩。

## 结果和下载内容

- 表格：编号、中文类别、置信度与原图像素xyxy坐标；界面分数保留4位小数、坐标保留2位用于显示。
- CSV：保留原预测分数及坐标精度，字段为id/class_id/class_name/confidence/x1/y1/x2/y2。
- JSON：原图尺寸、逐框预测、实际模型文件相对路径及SHA256、设备、conf、NMS IoU、尺寸、普通/SAHI/融合设置和绘图开关。
- 单次处理耗时可能包含首次模型加载、读图与绘图，不能当稳定FPS、完整网页延迟或GPU基准。

预测图、表格和下载来自同一组结果，不读取真实标注。**未标注单图不输出准确率、误检/漏检、召回率或F1；置信度不是准确率。**

导出文件保存在项目 `project_work/gradio_exports/request_*/`；Gradio本地图片缓存位于 `project_work/gradio_cache/`。清空界面不删除这些本地文件，也不改写输入原图和模型。上述目录由gitignore排除，不提交至GitHub。

## 同图双模型对照

切换“同图双模型对照”，上传一张原图并选择两份不同的正式单模型。两边共同使用普通640、同一conf与NMS IoU，默认.25/.7；绘图开关也共享。并排显示真实预测、两组逐框表、数量与单次耗时，可下载包含双方参数和预测的JSON。

不会使用历史模型代替五组基线，不运行训练，不把预测数更多说成召回更高。两模型加载/缓存状态可能不同，界面这次的耗时不能用于严格速度排名。正式比较见 [统一实验报告](experiment_report.md)。

所有预测请求使用同一串行队列与服务锁。运行期间锁住上传、清空与关键参数，结束或失败后恢复，避免旧结果对应到新上传图。

## 错误提示和边界

- 未上传、无效或超过4000万像素的图片：先给出提示，不加载模型；建议缩小原图。
- 缺权重、哈希不符、类别不是0=hat/1=person：拒绝使用，不静默换模型。
- 显存/内存不足：提示普通640单模型、关闭占用程序，或显式使用CPU；不自动降参数后套用原成绩。
- 其他图片/设备/推理/文件处理失败：显示可理解的错误，详细诊断留在启动终端。
- 每次请求不覆盖已有导出目录。模型元信息中的个人训练目录不复制到下载JSON。

代码许可与数据、权重、照片权利分别适用，见 [许可证规则](license_audit.md)。当前研究用途策略不补齐缺失授权，不提供商业可用承诺。
