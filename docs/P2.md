# P2 正式接入说明（2026-10-19）

P2 已接入模型配置、权重初始化和训练入口。本文的功能验证记录形成于 2026-10-19。2026-10-22 更新：作者已反馈标准版与 P2 训练完成，最终产物待归档核验；尚无可公开的新准确率或召回结果。仓库打包权重仍为历史演示模型。[当前状态](../reports/p2_progress.md)。

## 怎么检查、怎么训练

从项目根目录操作，使用项目内 Python 环境。

```bash
cd yolov8-learning

# 安全预检：验证数据和输入文件，不训练
.venv/bin/python -B train_helmet.py --variant standard --dry-run
.venv/bin/python -B train_helmet.py --variant p2 --dry-run

# 复现实验的新训练命令；已有完成产物不需要因此重训
.venv/bin/python -B train_helmet.py --variant standard
.venv/bin/python -B train_helmet.py --variant p2
```

`--variant` 选择网络结构；`--profile baseline640/highres960` 选择训练输入尺寸，默认640。P2并非Gradio里的切片选项，不会自动改变旧模型结构。

本地通过 datasets/current_training_dataset.json 选择已隔离的数据版本，训练/验证/测试为6488/511/508。GitHub 不包含本地数据登记文件；克隆后务必按[数据复现说明](../reports/scene_isolation/README.md)恢复划分，并在下列命令末尾显式追加 `--data datasets/helmet_scene_isolated_v1/data.yaml`，否则入口会回退到首轮去重数据。官方初始化权重须放在仓库根目录 `yolov8n.pt`，可在根目录执行 `python -c "from ultralytics import YOLO; YOLO('yolov8n.pt')"` 获取；入口会核验固定 SHA256。它与 models/ 下的安全帽演示权重用途不同。两种结构使用同一数据、50轮、batch=2、AdamW、lr0=0.001667、seed=0、nbs=64、mosaic=1、最后10轮关闭mosaic、scale=0.5、translate=0.1、mixup=0。其他参数由run.py统一提供，并保存实际生效配置。

标准版输出到runs/helmet_standard_isolated_640，P2版输出到runs/helmet_p2_isolated_640；同名已有目录由库递增命名，不覆盖。只有正式训练产出best.pt并通过数据身份复核，才登记训练产物。

## P2、P3、P4、P5是什么

它们是特征金字塔中的不同尺度。640输入下，P2/P3/P4/P5对应160/80/40/20的特征图，步长4/8/16/32。标准版使用P3/P4/P5检测；P2变体额外融合并输出P2尺度。原标准backbone已经有P2特征，本次增加的是相应融合和检测输出。

本次以官方YOLOv8 nano结构为基础，配置固定nc=2、scale=n，类别0=戴帽头部，1=未戴帽头部。P2不是本项目原创模块。官方P2变体也包含颈部和检测头的相应调整；该对照比较两种整体结构，不把结果归因于一个孤立组件。

## 预训练加载为什么没有直接全量按编号复制

新增P2支路会改变后续层的编号。按同编号且形状相同复制，不足以证明层的语义对应。

因此，两种实验配置都仅从同一份本地官方yolov8n.pt加载共有层0..15：完整backbone及共有的前两级颈部。共210个状态张量，逐层核对模块类型、输入连接、键名、尺寸和加载后数值。其余层保留新建时的固定种子初始化；固定DFL常量不称作随机参数。

这是本次对照明确规定的“共有层迁移”协议，不等同于Ultralytics默认的全量兼容参数迁移。两个变体采用相同加载覆盖范围。官方COCO的person是整个人，不能把这个类别名称直接当作本数据集的未戴帽头部；本协议没有迁移COCO分类检测头，也关闭跨类别名称重映射。

初始化后，通过库的对象加载API保留已初始化模型，再验证训练器重建时所有状态和共有参数保持一致。正式训练在第一次更新前还会重新校验共有参数哈希；失败立即停止。

每次正式训练会保存initialization.json、input_identity.json、command.json、environment.json和effective_args.json。initialization.json记录初始化阶段，不是新的训练成绩。

## 接入时已完成验证（2026-10-19，非最终训练评价）

- standard/P2均可构建，类别数2；640输入检测尺度分别为80/40/20和160/80/40/20。
- 两种结构共有预训练参数和状态的哈希完全相同，共有范围之外的参数没有被官方权重意外覆盖。
- 使用库的真实训练器get_model方法重建，全部状态与传入模型一致，初始化不会被悄悄丢弃。
- 两张现有训练原图经过确定性的640等比缩放和补边，损失有限，反向梯度有限，最细检测尺度的分类梯度非零。
- 没有执行optimizer.step，没有保存任何.pt检查点，没有更新正式模型登记。临时BatchNorm运行统计仅存在于检查进程内。
- 48项测试通过，standard640/P2640/P2960三个无训练预检通过；主对照除结构及输出目录外，训练参数相同。
- 原始数据、隔离清单、人工核查记录、官方和历史模型、检测网页代码均保持原哈希。

本次检查使用CPU，不是完整训练性能测试。当前执行环境未发现可用的MPS/CUDA，尚未测量实际训练设备的显存峰值和每轮耗时。开始正式训练前，运行` .venv/bin/python -B run.py check `确认实际设备，再按测速安排预算；不要据此认为50轮会很快。

## 文件在哪里

- models/configs/helmet_yolov8n.yaml：标准版固定配置。
- models/configs/helmet_yolov8n_p2.yaml：P2固定配置。
- models/configs/sources.json：上游来源、版本和文件指纹。
- helmet_models.py：共有层初始化和核对。
- train_helmet.py：结构与分辨率选择。
- run.py：训练执行与产物记录。
- reports/p2_integration/：公开的接入检查结果与初始化记录。
- reports/scene_isolation/：数据版本证据。

恢复中断训练应使用run.py train --model明确的last.pt路径 --data原数据配置 --resume，不重新指定--pretrained。训练入口的标准/P2新实验模式不会把旧安全帽模型作为起点。
