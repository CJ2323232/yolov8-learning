# 项目技术复盘：安全帽检测、数据审计与本地演示

[项目首页](../README.md) · [代码与运行流程](WORKFLOW.md) · [简历表述与证据索引](RESUME.md)

## 任务与完成范围

基于 Ultralytics YOLOv8n 和 SHWD，检测戴安全帽及未戴安全帽的头部。项目完成了标签转换、历史训练实验、结果评价、外部图片预测与 Gradio 本地演示；后续审查发现数据重复，补充了数据审计、流程修复及沿用旧权重的复评。

项目采用成熟检测框架，主要实践是数据处理、实验管理与应用集成。网络结构与训练框架来自 Ultralytics，没有原创架构或已验证算法性能提升的主张。

## 技术问题一：标注含义要先于界面功能

SHWD 的 `hat` 是戴帽头部，`person` 是未戴帽头部。将 person 当作整个人体，或把任意安全帽物体都当作正确结果，会改变任务定义。

转换程序检查类别、尺寸、框边界和无效数值，保存 difficult/truncated 元数据。当前采用 difficult 作为普通目标的训练与评价协议，并未复现 VOC difficult-ignore 协议。Gradio 对模型类别映射进行校验，再展示框与数量。

证据：[转换程序](../voc_to_yolo.py)、[界面实现](../app.py)、[标注协议](WORKFLOW.md)。

## 技术问题二：图片数量不能保证测试独立

历史训练共使用 6,064 张训练图、758 张验证图，另有 759 张测试图。审计发现 7 组 train/val、5 组 train/test 字节重复；全源数据有 37 组同图不同标注，共 74 个版本。

修复流程隔离全部冲突版本，而不是随意挑选一个框集；生成 6,005 / 750 / 752 的新划分，并记录图片、标签哈希及分组信息。完全相同图片的跨集合重复已排除，但近重复和同一拍摄场景仍需进一步复核。

一次重要经验是：**随机划分只决定文件去向，并不自动保证样本相互独立。** 已训练模型也不能直接在重新打散后的测试集上声称独立评价，因为其中可能包含该模型以前见过的训练图片。

证据：[审计与修复记录](FIXES_2026-10-13.md)、[数据审计 JSON](../reports/clean_dataset_audit.json)、[划分代码](../split_dataset.py)。

## 技术问题三：用已有模型回答有限但清楚的问题

为保留已有训练工作的价值，复评只筛选原测试集，没有把原 train/val 移入 test。结合文件哈希、解码像素哈希、感知特征与局部几何关联，先冻结筛查规则和名单，再评价模型。

最终保留 474 张图片、4,816 个框；相同权重在该子集的 mAP50 为 0.9173，mAP50–95 为 0.6063。排除的 285 张包含确认重复、测试内部冗余及未确认候选，不能全部算作泄漏。

这次工作回答的是“同一模型在筛查后的原测试子集上表现如何”，不证明模型提升或完全独立的泛化能力。原图、原标签和模型均保留，筛查与评价没有重新训练。

证据：[完整复评报告](../reports/legacy_test_reassessment.md)、[逐图决策](../reports/legacy_test_review/screening_decisions.csv)、[原始数据未改写的核验](../reports/legacy_test_review/verification.json)。

## 技术问题四：精度和耗时需要放在同一条件下讨论

历史尺寸实验固定权重与 758 张验证图，对比 416 / 640 / 960。960 相比 640 的 mAP50–95 高 1.62 个百分点，但该次 CPU 模型推理耗时约为 2.2 倍。

这提供了输入尺寸取舍的初步证据。历史验证划分存在重复、每档只测一次、计时不含网页流程，因此不作稳定速度或独立泛化结论。下一步应预热后重复测量，并单独记录端到端耗时，而不是把模型耗时直接换算成应用吞吐率。

证据：[实验条件](../reports/size_comparison.md)、[原始数值](../reports/size_comparison.json)。

## 技术问题五：置信度高，也可能违背任务定义

外部图片中，地上的安全帽被以约 0.79 的置信度识别为 hat。对“戴帽头部”任务而言，这是误检。可能与模型依赖帽子外观有关，但这是待验证解释，不能由一张预测图证明模型内部机制。

手持安全帽负例与小目标遮挡图片也被记录。15 张外部照片没有人工真值框，支持案例讨论，不能用于报告外部 mAP 或漏检率。

证据：[失败与边界案例](../reports/failure_cases.md)。

## 技术问题六：加切片并不保证整体变好

在单图上观察到SAHI补回小人头，同时增加错误安全帽框后，先冻结529张原验证集筛查名单，再固定模型和阈值比较640/960/1280切片。结果显示部分小目标召回提高，但整体F1均低于普通检测。

进一步重放合并过程，定位到小图只有一块时仍执行额外IOS合并。修复后对全部529张实跑，补回旧版丢失的48个匹配，却同时增加80个未匹配预测。修正版相对普通模式净多匹配19个，未匹配预测多308个，F1为88.20%，低于普通的90.33%。最终保留普通检测默认，把SAHI保留为可选实验方案。

这次工作展示了从现象、固定条件对比、后处理定位、代码回归到复验和取舍的完整过程。没有重训或宣称泛化提升；使用历史验证数据的限制仍适用。证据：[完整报告与复现](../reports/sahi_evaluation.md)。

## 工程上如何避免用错模型

训练流程保存实际 best.pt 路径、模型与数据清单哈希、有效参数及环境。评价和尺寸比较选择已登记产物，遇到数据或权重变化时停止；没有新产物时不静默回退到旧模型。网页允许明确标记的历史演示，因此仍可直接体验。

目前已验证修复流程与小规模训练/评价衔接，尚未完成新划分正式训练。小规模检查只证明流程可用，不作为正式精度成绩。

证据：[流程管理](../workflow.py)、[验证记录](../reports/fix_validation.json)、[回归检查](../tests/test_workflow.py)。

## 演示与下一步

演示顺序：上传一张图片 → 调节置信度 → 查看检测框与分类统计 → 展示一个失败案例 → 指向对应实验记录。模型可下载，应用在本地运行，尚未部署公网。

下一阶段优先利用已有标注，整理漏检与误检及其场景特点；之后重复计时、选择验证集阈值，再决定是否开展新训练。研究假设、尚未完成的任务和已测得的结果分别记录。
