# 分组隔离与下一轮优化准备（2026-10-19 历史计划）

> 2026-10-22：下文保留当时准备阶段记录；作者现已反馈两版训练完成，后续以[当前进度与评价方案](../reports/p2_progress.md)为准，无需因阅读本计划再次训练。

已生成独立数据版本 `datasets/helmet_scene_isolated_v1`，未启动训练。

## 做了什么

- 保留首批20组人工选择：10同组、9不同组、1不确定；原核查文件逐字节保留。
- 将已检索的20466对关联候选按“风险隔离桶”同分区放置。隔离桶不等于已确认同场景；不同照片可以为了保守隔离放在同一分区。
- PartA来自教室监控视频。将本地1999张PartA整体放在训练分区，避免同一固定机位不同时间出现在评价中。没有声称这1999张是一个场景。
- 保留全部7507张接受图片，新版本中491张改变分区归属，图片和标签内容未改。采用APFS写时复制，不是硬链接；原版本保持不动。
- 新划分：训练6488、验证511、测试508。优先少改原归属，没有强凑80/10/10比例。
- 当前训练入口已指向新版本；构建未完成、文件篡改、隔离约束被破坏时会停止。

## 已加入的系统改进

1. Gradio普通检测增加640/960输入选项，默认640。使用同一模型即可比较，无需为了切换分辨率重新训练。SAHI参数及单切片修复保持原协议。
2. 训练前增加 `--dry-run`：完整验证数据并显示参数，不加载检测模型、不训练。
3. 准备baseline640和highres960两个可复现配置。均为官方YOLOv8n预训练起点、50轮、batch=2、AdamW、lr0=0.001667、seed=0、nbs=64、mosaic=1、最后10轮关闭mosaic、scale=0.5、translate=0.1、mixup=0。两个配置只改变输入尺寸与输出目录名。

这些改进准备了可验证的方案，并不代表召回已经提高。更大的输入保留更多缩放后细节，同时增加计算量和显存需求，误检可能改变。训练集像素统计见training_resolution_diagnostic.json；它只分析标注框缩放，不是准确率结果，不含随机数据增强。

## 为什么之后仍需一次新基准训练

旧模型见过现有数据中的一部分图片；重新分组不会消除模型已学到的信息。不能把旧模型在新评价集的成绩当作独立结果，也不能通过接着旧best.pt微调洗掉这种关系。旧模型、历史曲线、SAHI实验仍作为历史记录保留。

可以等这一轮数据和系统准备完成，再训练一次baseline640。之后在验证集用同一权重比较640与960推理、记录分类别AP、固定阈值误检/漏检和稳定时延，不需第二次训练。只有要单独证明“960训练是否优于640训练”，才需要highres960第二组训练。当前没有承诺一次训练证明所有改动有效。

## 后续顺序

1. 当前阶段：核对本报告的数据范围和代码准备；不要继续逐对翻全部候选。
2. 确定训练设备和预算后，先做一次新的baseline640训练。Windows若有NVIDIA GPU可迁移；Mac同样可运行，但时间和960内存需求需在设备上检查。
3. 只在验证集选择推理分辨率与置信度，关注hat/person分开表现、小目标召回、每图误检和耗时。
4. 冻结最终方案后再评价test。若继续用test调参，应另建新测试集。

## 重要范围限制

已确认10对跨分区数为0；已检索20466对候选跨分区数为0。检索不是穷尽的，没有证明所有未知同源场景都已发现。

val/test没有PartA教室来源，因此结果适用范围是剩余来源的安全帽/头部检测，不能宣称泛化到新教室。后续若要评估教室泛化，需要真实camera/video来源分组或新场景数据。保守隔离可能把不相关照片也放在同一桶内，这是数据利用效率的代价。

## 验证

40项单元测试通过；2张训练原图完成640/960/640真实推理检查，默认640图像输出及计数与原路径一致；Gradio960回调通过。两个训练配置均通过完整预检。原数据、标注、模型、核查记录哈希保持不变。没有训练，也没有计算或宣称新的性能提升。
