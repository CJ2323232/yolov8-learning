# 标准版与P2融合：阈值校准与固定参数测试

2026-10-24 · 推理与后处理实验，没有重新训练。

所选融合方案通过预设的测试集指标筛选条件，但仍需权衡速度和提升幅度。

验证集选出 P2 与 NMS 合并 作为主要比较。测试集上，融合相对单模型召回率变化 +0.47 个百分点，精确率变化 +0.27 个百分点，F1 变化 +0.37 个百分点；漏检变化 -23 个，未匹配预测变化 -12 个。CPU 实测平均耗时为单模型的 1.71 倍。

安全帽类别单独看：融合少漏 9 个，但未匹配预测增加 23 个，精确率从 91.40% 变为 88.90%。因此总体指标改善不等于每一类都改善。当前更适合保留为可选实验方案，暂不因这次小幅提升替换默认检测模式。

## 做了什么

1. 核对数据清单、7507张图片及标签哈希、跨分区隔离约束和两个 best.pt 身份。
2. 使用现有标准版和P2权重，以640输入、CPU单图方式对511张验证图重新推理；保存置信度≥0.01的候选框，每模型最多300框。没有训练。
3. 固定 NMS/WBF 的融合 IoU=0.55、WBF等权平均分数。分别扫描0.05～0.95（步长0.01）的最终阈值，要求验证集未匹配预测≤759，优先保留最多匹配目标。相同预算不保证最终数量完全相同。
4. 冻结四个阈值、主要单模型与主要融合方案及其哈希。随后推理508张测试图片，只用冻结参数评价一次，没有按测试结果重新选阈值或更换主要比较。
5. 对24张按文件名均匀选出的验证图片，每种方案预热后实测两轮，每轮24次。分别在独立进程加载所需模型，记录CPU耗时和进程峰值内存。
6. 按类别和目标尺寸统计测试集表现；按已有风险隔离组做2000次配对重采样，估计本批测试图片上的结果波动。

## 结果波动

## 限制与诚实结论

- 未匹配预测是相对已有标注的计数，可能含漏标、定位偏差、重复或类别错误，不能全部叫作人工确认误检。
- 这里是固定阈值、同类一对一 IoU≥0.5 的微平均 P/R/F1，不是 mAP，也不能直接与训练日志的最大F1阈值类别平均 P/R 比较。
- 测试集沿用已有数据；历史项目已经使用过其中部分原始图片或相关图片。这轮没有用测试集调参，但不能称为全新外部盲测，也不证明所有未知同场景关系均已隔离。
- 重采样区间基于已有风险组，可能跨过0；不是多次训练稳定性结论，也不能证明模块必然有效。测试集结果出炉后若继续据此改算法，它将成为开发数据，后续严格最终评价需另留数据。
- 候选置信度下限0.01和最多300框限制仍存在；到达上限的图片数量已记录。此次不计算完整PR/AP。WBF置信度经融合重标度，因此阈值与单模型不同。
- CPU计时包含图片读取解码、模型预测、融合和最终过滤，不含首次加载模型、绘图、保存、网页/网络。文件缓存已预热，测量受本机后台负载与温度影响，不能推算RTX 3060速度。
- 内存是整个Python进程的峰值RSS，含库、模型、预热和一致性检查；本机没有可用CUDA，本次没有测游戏本显存。
- 线程执行偏差：协议最初请求4线程，但当前Ultralytics在CPU初始化时自动重设为8。计时实测四种方案均为8线程并逐次断言一致；推理阶段使用相同初始化代码，未逐图记录线程数。保留原协议与初次计时记录，明确披露偏差。
- 运行预检遇到零面积边界框，统一过滤并计数；v1部分缓存保存在preflight_retry_v1，修复后全部重新生成。没有基于评价成绩修改该规则。

上述实验于2026-10-24完成；2026-10-25公开本证据副本并将融合接入Gradio可选方案。原始实验记录不回写，verification.json中的github_published=false和gradio_default_changed=false表示实验完成时状态。CUDA速度/显存仍需在游戏本实测。
